## Credit and reservation contract

- App policy: 8,000 credits per trailing 24 hours; 800 per trailing hour. GeoNames free policy is 10,000/day and 1,000/hour, identified by username. The app thresholds leave 20% headroom; requests are not universally credits. [Official limits](https://www.geonames.org/export/).
- Only the actual `searchJSON` (every page) and `getJSON` (selected ID resolution) endpoints are priced at one credit. Search is explicitly one; get uses the documented default for other services. Unknown paths/hosts fail closed instead of inheriting that price. [Credit schedule](https://www.geonames.org/export/credits.html), [get service](https://www.geonames.org/export/web-services.html#Get).
- One operator-prepared `APP_CREDITS_V1` row in GeoNamesDailyQuota replaces request-time daily create. No create/upsert/reseed in app traffic. Missing, legacy-only, duplicate, malformed or future-clock state blocks. Existing legacy daily rows remain untouched and are not interpreted as unused budget.
- A bounded two-row lookup with five-field projection identifies exactly one singleton. Read state, compute bounded buckets, then single-ID `updateMany` with scope/revision/window predicates; increment revision and replace bucket state in the same operation. Only `{success:true,updated:1,has_more:false}` permits fetch. Verified zero matches returns a short contention wait. Malformed/failed/lost acknowledgement returns safe unavailability, with no automatic increment retry or refund. A committed-but-unacknowledged reservation conservatively consumes capacity.
- At most 25 UTC-hour buckets retain the current hour plus 24 prior buckets; their sum enforces the daily cap. The newest two enforce the hourly cap. This is conservative: credits can remain counted for up to 25h/day and 2h/hour. Crossing midnight/hour does not erase adjacent usage. Retry-After points to the earliest bucket expiration allowing the reservation; both limits must permit it. UTC is an indexing convention, not a claim about provider reset alignment.
- Existing 30 app requests/user/minute, 60 upstream attempts/user/minute and 300/worker/minute remain local. Local slots are now reserved before awaiting the database, preventing async quota waits from bypassing the worker burst check. Cache/in-flight hits do not touch the durable counter or provider. Aborted provider requests cannot dispatch after a slow reservation finishes. Counters may conservatively retain unused reservations.
- Onboarding search/page and profile selected-ID save, and You selected-ID save, share this durable scope. The You birthplace picker searches through the existing onboarding service. Authorization/ACTIVE/privacy/lifecycle checks occur before quota IO; no new client identity or direct counter API exists.
- Backend 429 Retry-After/body seconds are retained; services preserve bounded `retryAfterSeconds`. TR/EN says temporarily limited, selections kept, try later, with no minute/reset promise. Query, confirmed selection and profile draft remain; retries stay explicit. No countdown or auto-resend was added.

The current Base44 documentation describes conditional single-ID updates and testing `updated`; it explicitly warns that concurrent upserts can duplicate keys. It does not supply a unique-key bootstrap guarantee. [Entities contract](https://docs.base44.com/developers/references/sdk/docs/type-aliases/entities).

Both exact SDK packages (frontend installed **0.8.57**, backend pinned **0.8.54**, unpacked separately without upgrading) execute the real entity module against injected HTTP transport: query/operators reach PATCH `/update-many` unchanged and the response passes through. Accepted/zero/malformed/lost cases are checked in [SDK receipt](geonames-quota-053/sdk-transport.json). Actual TS entries, real handlers and lifecycle/write wrappers are tested with synthetic SDK imports in [entry receipt](geonames-quota-053/entry-boundaries.json). Deno executable is unavailable: Deno runtime integration **NOT_RUN**. Hosted atomic enforcement and multi-worker contention **NOT_RUN**, not implied by docs or fixtures.

The algorithm's shared bound assumes the platform enforces the documented single-record conditional write and authoritative reads, a single prepared counter, sane server clocks and the complete new entry/shared graph. Operators must not reset/clone it while traffic runs. Unexpected external writers, mixed old workers and independent consumers of the same GeoNames username are outside this app counter. Reservation time is not proof of provider receipt time. No distributed mutex, transaction, exactly-once delivery or absolute provider-account quota guarantee is claimed.

## DB cost and operational limits

Old admitted existing-row miss: 1 read + 1 unconditional write. New admitted miss: **1 projected two-row read + 1 single-ID conditional write**. Limit denial: 1 read / 0 writes. Cache/in-flight hit: 0/0. Missing/duplicate/malformed record: 1/0. DB write error or unknown reply: at most 1/1, no automatic retry. 20 simultaneous contenders: 20 reads + 20 conditional attempts, one admission at 2/3; no local lock presented as distributed authority. Fixed maximum 25 small bucket objects, rather than per-user data or per-request rows. Payload/call measurements are in [quota-cost.json](geonames-quota-053/quota-cost.json): conditional query/patch JSON is 189 bytes for one bucket, 861 bytes for all 25; 20 contenders total 3,780 bytes. These are serialized application fields, excluding SDK/HTTP headers. Wall-clock synthetic CPU numbers are not hosted DB latency or screen-speed evidence.
