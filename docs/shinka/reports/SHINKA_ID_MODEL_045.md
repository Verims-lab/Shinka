## Decision and implemented changes

MessagePair is the sole message/suggestion text authority. Existing daily native ID, user, local day, timezone, category, message_pair_id and generated_at stay unchanged. Later MessagePair edits may change historical displays: this is explicitly approved, superseding the original SRC-05/07 immutable text contract. The original source receipt and historical reports remain intact; no version/archive table was added.

The committed UserDailyMessage physical schema retains four optional legacy string fields without defaults. The logical validator and new writer still exclude them; existing stored values are ignored on reads and remain physically present until cleanup. New UserDailyMessage rows contain no `message_tr_snapshot`, `suggestion_tr_snapshot`, `message_en_snapshot`, `suggestion_en_snapshot`. Compatibility response names are derived from the current Pair. Old text mismatch never blocks a valid reference; missing/bad references return safe reference-stage/ID diagnostics and the existing friendly error, never random replacement. Existing inactive Pair references are readable; new selection excludes Inactive. Import remains exact-source and refuses conflicts rather than overwriting later approved text edits.

`dailySelectionLibrary` uses projected category/mapping/eligibility metadata; `dailyContent` resolves unique IDs in batches of 100 (4000 IDs ceiling). Only the selected Pair text is read during generation; repeated/history reads do not download every content text. Reconciliation compares assignment category/pair, not legacy copies. Pattern's six-field projection is preserved. Kept-mounted Home reactivation reads current text; it retains main's tab/scroll behavior. No persistent content cache or second content store.

NotificationDelivery now verifies every relevant daily_message_id through one bounded projected owner/date query before acting. Missing/foreign/malformed links block dispatch; native IDs are never rewritten. This adds a read per nonempty delivery reconciliation; no existing query budgets were raised, and provider remains disabled. Previously accepted/unknown sends are not recalled or blindly resent.
