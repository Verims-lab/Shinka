## Chosen Base44 primitives

Installed SDK **0.8.54** was compared with [entity methods](https://docs.base44.com/developers/references/sdk/docs/type-aliases/entities) and [entity schemas](https://docs.base44.com/developers/backend/resources/entities/entity-schemas), checked 2026-10-20. `create` inserts; `update` merges; `upsert` merges matching keys and can overwrite existing snapshots. `updateMany(query, data)` returns `success`, `updated`, `has_more`; `deleteMany` returns `success`, `deleted`. Filtered update with exact previous value and count/readback narrows and detects conflicts; **it is not documented linearizable compare-and-swap**. Native UNIQUE is unsupported. No Entity multi-collection transaction, rollback, lock, visibility bound or distributed uniqueness is claimed.

[Actors](https://docs.base44.com/developers/backend/resources/actors/overview) offer actor lifecycle and persisted key/value state, but process memory resets on idle/restart and does not supply an Entity transaction. Ordinary Entities/functions were selected: fewer authorities and no actor-to-Entity commit bridge. No new generic coordinator, service or worker-local lock is presented as a distributed guarantee.
